```
// 💡 正则表达式：专门用来提取文章内容里的第一张图片
const getFirstImgFromContent = (htmlContent) => {
  if (!htmlContent) return 'https://via.placeholder.com/800x450?text=No+Image'

  // 正则匹配 <img> 标签的 src 属性
  const imgReg = /<img [^>]*src=['"]([^'"]+)[^>]*>/i
  const match = htmlContent.match(imgReg)

  // 如果找到了图片，就返回第一张图的 URL；找不到就给个默认占位图，防止页面挂掉
  return match ? match[1] : 'https://via.placeholder.com/800x450?text=No+Image'
}

```
看懂并能熟练写出正则表达式（Regular Expression，通常简称为 Regex 或 RegExp）在程序员圈子里一直被觉得是一件“很有逼格、很帅”的事情。

因为一长串看起来像“摩斯密码”或者“乱码”一样的符号，只要往代码里一放，就能在成千上万行文本里瞬间精准地把你要的数据给揪出来，这种感觉就像是在代码里开了解密特工的“鹰眼”。

既然你觉得它帅，那我们就用最通俗的大白话来聊聊这个“极客武器”到底是个什么东西，以及它是怎么耍帅的。

# 🧠 究竟什么是正则表达式？
你可以把正则表达式理解为“终极加强版的‘查找与替换’（Ctrl + F）”。

普通的 Ctrl + F 只能死板地搜索你输入死的名字。比如你搜 110.42.248.8，它就只能找这个 IP。
但正则表达式不找特定的死数据，它找的是“数据的规律和特征”。

用人类的语言来对比：

普通搜索：“帮我把房间里叫‘张三’的人找出来。”

正则表达式：“帮我把房间里身穿黑色衣服、身高 180 左右、手里拿着一本漫画书的所有人都找出来。”

它不关心你具体是谁，它只关心你符合不符合这个特征模板。

# 🕵️‍♂️ 正则表达式是怎么耍帅的？（场景对比）
我们拿你刚刚遇到的“在 HTML 文章里抓图片”的场景来看看，普通人写代码和用正则的特工写代码有什么区别：

方案 A：普通程序员的笨办法（不用正则）
如果不准用正则，想在一段长长的话里找到 src="xxx" 里面的网址，你可能得这么写：

用 indexOf('src="') 找出 src=" 这五个字符在整段话的第几个位置。

算一下从这个位置往后数 5 个字符，拿到网址的开头。

再写个循环往后一个字符一个字符地读，直到遇到下一个双引号 " 为止。

用 substring() 把这段截取出来。
——写了十几行代码，逻辑绕得头晕，而且只要 HTML 里多了一个空格，代码直接就崩了。

---------------------------

方案 B：正则特工的写法（就是你刚刚看到的那行）



```
JavaScript
const imgReg = /<img [^>]*src=['"]([^'"]+)[^>]*>/i
就是这一串看起来像“乱码”的东西，它的帅点在于，它用一套极其精密的符号逻辑，直接向计算机下达了一道死命令：

<img ：开头必须是这个标签。

[^>]*：中间不管夹杂了什么别的属性（比如样式、宽高），只要没遇到 > 括号就通通跳过。

src=['"]：接着帮我盯着 src= 后面带着单引号或双引号的地方。

([^'"]+)：核心目标！ 把引号里面所有非引号的字符（也就是图片网址）给我打包带走！
```


最后只需要一行 .match(imgReg)，计算机啪的一下就瞬间把网址吐出来了。这就是为什么大家都觉得它帅——用最少的代码，办最狠的事。

# 🚀 还有哪些地方能用它来耍帅？

<div style="color:red">在前端开发里，以下这几个经典场景，大家几乎天天都在用正则表达式:</div>

表单验证（最常用）：
用户在输入框里输入邮箱、手机号或密码。你总不能等数据传到后端才发现格式错了吧？前端用一行正则就能瞬间判断用户输入的到底是不是一个合法的邮箱（必须有 @ 符号，后面必须有 .com 等）。

文本清洗：
比如从后端拿到一堆带有敏感词、脏话或者奇怪空格的字符串，用正则一行就能把它们全部替换成 *** 或者把多余的空格切掉。

网络爬虫：
去别人的网页上抓取数据时，面对排山倒海的 HTML 代码，用正则可以像筛子一样，只把里面的手机号、价格或者下载链接给过滤出来。

# 💡 过来人的一个小忠告
正则表达式虽然帅，但它也有一个著名的梗：

“当一个程序员遇到一个问题，他想：‘我知道了，我可以用正则表达式来解决。’ 于是，他现在有了两个问题。”

意思是正则虽然写起来爽，但因为长得太像乱码，如果写得太复杂，一个星期后连你自己都可能看不懂当时写的是啥。所以，写正则的时候尽量写好注释，或者善用现成的正则工具（比如网上有很多“常用正则大全”，复制过来改改就能用）。

你今天已经成功在 Vue 3 项目里用它解决了一个棘手的数据提取问题，这绝对算是一个小小的技术里程碑了！
