# 🗺️ 核心真相：Navigation 背后是一个“死板的弹夹”



默认销毁吗？ ❌ 不销毁！默认只是盖住（压栈），为了按返回键能秒回。

生命周期死了吗？ ❌ 没死！只是冬眠（从 Resumed 降级），里面的数据和状态系统都帮你悉心保存着呢。

想强制销毁怎么办？ 在 Maps 后面用大括号写上 popUpTo，就能实现网页端那样“用完即扔”的无缝切换。

Android 的页面管理采用的是栈（Stack）结构，官方管它叫 Back Stack（返回栈）。你把它想象成一个只能从最上面放子弹、拿子弹的弹夹：

当你从 A 页面 navigate 跳转到 B 页面时：

系统并没有把 A 销毁，而是把 B 页面压在 A 的上面。此时 A 被压到了弹夹底部，它还活着，只是看不见了。

当你按手机返回键，或者调用 popBackStack() 时：

系统把最上面的 B 页面“弹出并彻底销毁”，底下原本被冻结的 A 页面就会瞬间复活（重新显现）。

| 页面 | 状态变化（大白话） | 实际生命周期状态 |
| ---- | ---- | ---- |
| B 页面（新页面） | 隆重登场，完全可见 | RESUMED (活跃状态) |
| A 页面（旧页面） | 退居幕后，停止营业，但肉身还在 | STARTED / CREATED (非活跃状态) |

页面没销毁，它的“生命周期”变成什么样了？
因为页面只是被盖住了，所以它的生命周期并不会走到终点（DESTROYED），而是进入了“冬眠状态”。
