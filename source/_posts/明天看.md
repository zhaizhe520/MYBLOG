## 3. さ・げ・み 整理

| 形式 | 功能 | 例 |
| --- | --- | --- |
| さ | 客觀可測量的程度、量 | 温かさ＝溫度；重さ＝重量；深さ＝深度 |
| み | 內心感受到的質感、味道、深意 | 温かみ＝人情味；重み＝分量；深み＝深奧；甘み＝甜味；苦み＝苦味；面白み＝趣味；親しみ＝親切感 |
| げ | 那種樣子、神情 | 寂しげ、不安げ、楽しげ |
| そう | 外觀樣態 | 温かそう |

### 重點

- 「温かさ」＝溫度程度；「温かみ」＝人情味、氛圍的溫暖。
- 固定搭配：温かみのある声／温かみのある色。
- N2 常考：重さ／重み、深さ／深み、親しさ／親しみ。
- 情感、人情、藝術評價用「み」；數值、物理量用「さ」。
- 易錯點：不是所有形容詞都能自然加「み」，要當固定詞彙記。

## 一、数据结构总览

### 1.1 数据结构分类树

```txt
数据结构
├─ 线性结构（一个接一个）
│   ├─ 数组 Array          → 按下标随机访问
│   ├─ 链表 Linked List    → 靠 next 指针串起来
│   ├─ 栈 Stack            → 后进先出 LIFO
│   └─ 队列 Queue          → 先进先出 FIFO
│
├─ 键值/集合结构（靠哈希或排序找）
│   ├─ Map 映射            → key → value
│   ├─ Set 集              → 只存 key，不重复
│   └─ 对象 Object/Record  → 字符串 key → value 的轻量 Map
│
├─ 树形结构（分层）
│   ├─ 二叉树
│   ├─ 二叉搜索树 BST
│   ├─ 堆 Heap
│   ├─ 平衡树（AVL / 红黑树）
│   └─ Trie 字典树
│
└─ 图结构（任意连接）
    ├─ 有向图 / 无向图
    └─ 加权图
```

### 1.2 数据结构对比表

| 结构 | 核心特征 | 常见访问方式 | 优点 | 注意点 |
|---|---|---|---|---|
| 数组 Array | 连续下标 | `arr[i]` | 随机访问快 | 中间插入/删除成本高 |
| 链表 Linked List | 节点 + `next` 指针 | 从头遍历 | 插入/删除灵活 | 不能按下标随机访问 |
| 栈 Stack | 后进先出 LIFO | `push/pop` | 表达式、回溯、撤销 | 只能操作栈顶 |
| 队列 Queue | 先进先出 FIFO | `push/shift` 或入队/出队 | 排队、任务调度 | 普通数组 `shift` 可能 O(n) |
| Map | key → value | `get/set/has/delete` | key 可为对象，查找快 | 不是普通对象 |
| Set | 只存不重复值 | `add/has/delete` | 去重 | 不存 key → value |
| Object/Record | 字符串/Symbol key | `obj.key` | 轻量、字面量方便 | 原型链、可枚举性要注意 |
| BST | 左小右大 | 中序遍历有序 | 有序查找 | 可能退化成链表 |
| Heap | 堆序性质 | 取堆顶 | 优先队列 | 不是全局有序 |
| Trie | 按字符分层 | 逐字符走 | 前缀查询快 | 占空间 |
| 图 Graph | 顶点 + 边 | BFS/DFS | 表达任意关系 | 注意环、权重、方向 |

### 1.3 线性结构对比

| 对比项 | 数组 | 链表 | 栈 | 队列 |
|---|---|---|---|---|
| 访问方式 | 下标随机访问 | 沿 `next` 顺序访问 | 只访问栈顶 | 只访问队头/队尾 |
| 插入删除 | 中间较慢 | 改指针较快 | 栈顶快 | 队头/队尾快 |
| 顺序规则 | 下标顺序 | 指针顺序 | 后进先出 | 先进先出 |
| 典型场景 | 列表渲染、缓存 | LRU、节点串联 | 撤销、括号匹配 | 任务队列、BFS |

### 1.4 键值/集合结构对比

| 对比项 | Map | Set | Object/Record |
|---|---|---|---|
| 存什么 | key → value | 只存值 | 字符串/Symbol key → value |
| key 类型 | 任意类型 | 值本身 | 字符串或 Symbol |
| 是否可重复 | key 不重复 | 值不重复 | key 不重复 |
| 遍历 | `for...of` 得 `[k,v]` | `for...of` 得值 | `for...in` 得可枚举键 |
| 适合 | 字典、缓存 | 去重、集合运算 | 配置、轻量记录 |

## 三、迭代、迭代器、枚举 iterator

### 3.1 核心概念

迭代就是：一个对象只要实现了 `[Symbol.iterator]()`，返回一个带 `next()` 的迭代器，它就能被 `for...of`、展开、解构等统一消费。

- 数组、Map、Set、字符串有 `[Symbol.iterator]`。
- 普通对象默认没有。
- 核心是面向协议编程，不是面向具体数据结构编程。

### 3.2 迭代架构

```txt
数据源
  ├─ Array / Set / Map / String / DOM 集合
  ├─ 自定义对象：实现 [Symbol.iterator]
  └─ 生成器 / 异步生成器

        ↓ 实现可迭代协议

Iterable 可迭代对象
        ↓ [Symbol.iterator]()

Iterator 迭代器（有状态游标）
        ↓ next() 反复调用

IterationResult { value, done }
        ↓

消费端
  ├─ for...of
  ├─ 展开 / 解构 / Array.from
  ├─ Map/Set 构造
  └─ 自定义算法：map/filter/take/sum
```

### 3.3 两种协议对比

| 协议 | 要求 | 作用 |
|---|---|---|
| 可迭代协议 Iterable | 对象实现 `[Symbol.iterator]()`，返回迭代器 | 表示“可以被遍历” |
| 迭代器协议 Iterator | 迭代器有 `next()`，返回 `{ value, done }` | 表示“有一个有状态游标” |

### 3.4 术语对比：迭代、迭代器、枚举

| 术语 | 含义 | 关注点 |
|---|---|---|
| 迭代 Iteration | 一次一次取得下一个值的过程 | 过程 |
| 迭代器 Iterator | 带 `next()` 的有状态游标 | 推进器 |
| 可迭代对象 Iterable | 实现 `[Symbol.iterator]()` 的对象 | 数据源 |
| 枚举 Enumeration | 列举/遍历成员，常见于 `for...in`、对象属性列举 | 列举动作，不是 JS 专门协议 |

### 3.5 for 循环对比

```js
for (let i = 0; i < n; i++) {
  // 普通索引循环
}

for (const key in obj) {
  // 遍历可枚举属性名/键，常见于对象；不建议直接用于数组
}

for (const value of iterable) {
  // 遍历可迭代对象的值：数组、字符串、Map、Set 等
}
```

| 写法 | 遍历对象 | 得到什么 | 适合 |
|---|---|---|---|
| `for (let i = 0; i < n; i++)` | 下标 | 索引 | 数组、需要下标 |
| `for...in` | 可枚举属性 | 键/属性名 | 普通对象；数组慎用 |
| `for...of` | 可迭代对象 | 值 | 数组、字符串、Map、Set |
| `Map` 的 `for...of` | Map | `[key, value]` | 键值对 |
| `Set` 的 `for...of` | Set | 值 | 去重集合 |

### 3.6 自定义可迭代对象示例

```js
const range = {
  from: 1,
  to: 5,

  // 可迭代协议：调用它返回一个迭代器
  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;

    // 迭代器协议：必须有 next()
    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
};

for (const n of range) {
  console.log(n); // 1 2 3 4 5
}

console.log([...range]); // [1, 2, 3, 4, 5]
```

### 3.7 生成器简化状态机

```js
function* range(from, to) {
  for (let i = from; i <= to; i++) {
    yield i;
  }
}

console.log([...range(1, 5)]); // [1, 2, 3, 4, 5]
```

生成器本质上是帮助实现迭代器协议：`yield` 产出值，函数结束时 `done: true`。

### 3.8 面向协议编程

```txt
面向具体数据结构编程：
  if (是数组) 用下标
  else if (是 Map) 用 entries
  else if (是 Set) 用 values
  else if (是树) 递归

面向协议编程：
  只要实现 [Symbol.iterator]()
  就用 for...of / 展开 / 解构 / Array.from 统一消费
```

结论：迭代的架构是用最小协议把“数据源”和“遍历过程”分离，用外部拉取模型把推进控制权交给消费者，用语法糖统一消费方式，用生成器降低状态机实现成本，用异步协议扩展到异步世界。

## 四、IndexedDB 中出现的问题：Vue Proxy 与 structured clone

### 4.1 问题现象

Vue 3 的 `ref/reactive` 把对象包成 `Proxy`，带了一堆内部的依赖追踪属性。  
而 IndexedDB 写数据用 `structured clone` 算法，遇到 `Proxy` 会直接抛 `DataCloneError`。

```txt
Vue reactive/ref
  ↓
Proxy 对象
  ↓ 传给 IndexedDB
structured clone
  ↓
遇到 Proxy
  ↓
DataCloneError
```

### 4.2 错误示例

```js
import { reactive } from 'vue';

const state = reactive({
  name: 'Tom',
  age: 18
});

// 伪代码：把响应式对象直接写入 IndexedDB
// db.put(state, 'user');
// 可能抛出：DataCloneError: Failed to execute 'put' on 'IDBObjectStore'
```

### 4.3 解决思路

写入 IndexedDB 前，把响应式数据转换成普通纯对象。

```js
import { reactive, toRaw } from 'vue';

const state = reactive({
  name: 'Tom',
  age: 18
});

// 方式一：toRaw 解一层
const raw = toRaw(state);

// 方式二：JSON 深拷贝，简单但会丢失 undefined、Date、Map、Set 等
const plain = JSON.parse(JSON.stringify(state));

// 方式三：递归解包，适合嵌套 reactive
function toPlain(value) {
  if (value === null || typeof value !== 'object') return value;
  if (Array.isArray(value)) return value.map(toPlain);
  if (value instanceof Date) return new Date(value);
  const rawValue = toRaw(value);
  const result = {};
  for (const key of Object.keys(rawValue)) {
    result[key] = toPlain(rawValue[key]);
  }
  return result;
}

const data = toPlain(state);
// db.put(data, 'user');
```

### 4.4 原生 IndexedDB 异步回调问题

原生 API 常见事件回调：

```js
const request = indexedDB.open('my-db', 1);

request.onerror = () => {
  console.error('打开失败');
};

request.onsuccess = () => {
  const db = request.result;
  const tx = db.transaction('users', 'readwrite');
  const store = tx.objectStore('users');
  const putRequest = store.put({ id: 1, name: 'Tom' });

  putRequest.onsuccess = () => {
    console.log('写入成功');
  };

  putRequest.onerror = () => {
    console.error('写入失败');
  };
};
```

可以封装成 Promise，或使用 `idb` 这类库降低回调阅读成本。

```js
function openDB(name, version) {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open(name, version);
    request.onerror = () => reject(request.error);
    request.onsuccess = () => resolve(request.result);
  });
}

async function saveUser(db, user) {
  return new Promise((resolve, reject) => {
    const tx = db.transaction('users', 'readwrite');
    const store = tx.objectStore('users');
    const request = store.put(user);
    request.onerror = () => reject(request.error);
    request.onsuccess = () => resolve(request.result);
  });
}
```

### 4.5 关键结论

| 问题 | 原因 | 解决 |
|---|---|---|
| `DataCloneError` | IndexedDB 用 structured clone，不能克隆 Vue Proxy | 存前转普通对象：`toRaw`、深拷贝、递归解包 |
| 原生 API 回调多 | IndexedDB 是事件/请求模型 | Promise 封装或使用 `idb` |
| 嵌套响应式对象 | 只 `toRaw` 一层可能不够 | 递归解包或只存纯数据 |
| 复杂类型丢失 | `JSON` 深拷贝有限制 | Date/Map/Set 需特殊处理 |

## 五、综合对比总结

### 5.1 遍历方式对比

| 数据结构 | 常见遍历方式 | 得到什么 | 备注 |
|---|---|---|---|
| 数组 | `for`、`for...of`、`map/filter` | 下标或值 | `for...in` 不建议用于数组 |
| 链表 | 从头沿 `next` | 节点 | 不能随机访问 |
| 栈 | `pop` | 栈顶 | 后进先出 |
| 队列 | 出队 | 队头 | 先进先出 |
| Map | `for...of`、`entries()` | `[key, value]` | 键值对 |
| Set | `for...of`、`values()` | 值 | 不重复 |
| 普通对象 | `for...in`、`Object.keys` | 键 | 注意可枚举性 |
| 树 | 递归、栈、队列 | 节点 | DFS/BFS |
| 图 | BFS/DFS | 顶点/边 | 注意环和权重 |

### 5.2 协议与消费方式对比

| 消费方式 | 依赖什么 | 示例 |
|---|---|---|
| `for...of` | 可迭代协议 | `for (const x of arr) {}` |
| 展开 | 可迭代协议 | `[...set]` |
| 解构 | 可迭代协议 | `const [a, b] = arr` |
| `Array.from` | 可迭代协议或类数组 | `Array.from(map)` |
| `Map/Set` 构造 | 可迭代协议 | `new Set(arr)` |
| 自定义算法 | 迭代器 `next()` | `while (!(r = it.next()).done) {}` |

### 5.3 一句话记忆

```txt
数据结构解决“数据怎么组织”；
迭代协议解决“数据怎么统一遍历”；
IndexedDB 问题解决“响应式 Proxy 不能直接 structured clone”。
```
