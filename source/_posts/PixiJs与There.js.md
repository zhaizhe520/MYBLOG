| 维度 | PixiJS | Three.js |
| ---- | ---- | ---- |
| 核心定位 | 高性能 2D 渲染库 | 完整的 3D 引擎 |
| 最佳场景 | 2D 游戏、复杂 UI、H5 营销特效、数据可视化 | 3D 可视化、产品展示、轻量级 3D 游戏、VR/XR |
| 抽象层级 | 相对底层，聚焦于“渲染”本身 | 较高层，封装了完整的 3D 场景概念（相机、光照、材质等） |
| 性能特征 | 在 2D 实现中性能顶尖 | 在 3D 实现中性能远超同类 |

## PixiJS 核心组件层

Renderer（渲染器） ：系统的核心，负责将场景图绘制到屏幕。它会自动在 WebGPU 和 WebGL 之间选择，无需手动干预。

Container（容器） ：场景图（Scene Graph）的节点。所有可显示对象（精灵、图形、文本）都继承自 Container，通过父子关系构成渲染树。

Ticker（滴答器） ：提供基于时钟的周期性回调，是驱动游戏更新逻辑和渲染循环的引擎。可以同时存在多个 Ticker。

Assets（资源系统） ：异步加载和管理图片、音频、字体、精灵表等资源。

Application（应用） ：一个便捷封装，自动帮你组装好 Renderer 和 Ticker，适合快速原型和简单项目。

## 场景与渲染控制层

Scene Graph（场景图） ：理解父子变换、渲染顺序和剔除（Culling）机制。

Render Loop（渲染循环） ：掌握场景图更新与帧渲染之间的时序关系。

Render Groups（渲染组） ：将场景元素分组，以优化 GPU 批处理，提升性能。

Render Layers（渲染层） ：独立于逻辑层级来控制渲染顺序。

## 能力扩展层

PixiJS v8 的核心理念是一切皆扩展（Extension） ，这使得它保持轻量且高度可定制。你不需要深入扩展系统本身，但应了解其带来的能力：

交互与可访问性：指针事件（点击、悬停）、键盘导航和屏幕阅读器支持。

滤镜（Filters） ：包括自定义着色器，用于对可渲染对象施加视觉效果。

网格与高级图形：内置的 Mesh 类型，用于更灵活的图形渲染。

## 性能与工程化

GPU 资源管理：理解纹理等 GPU 资源的垃圾回收机制，避免内存泄漏。

性能优化技巧：通用的最佳实践与针对性技术，如利用 Render Groups 和 Culling。

TypeScript 支持：PixiJS 对 TS 有良好的支持，适合工程化项目。
