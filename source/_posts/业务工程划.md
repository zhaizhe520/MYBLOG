单一职责原则 (SRP)

那些是数据规则，哪些是页面渲染

状态是单一数据源

规则用纯函数

副作用放外层

页面只读状态

core:「原始数据 / 业务规则---->

composables组合式逻辑连接  做成响应式变量，包装好操作函数，处理浏览器存储，**适配 Vue 的响应式体系**

----> vue组件「页面组件 template」渲染层

不这样写 业务规则和 Vue 响应式混在一起 适合快熟成型

单向数据流

用户操作 → 视图层捕获事件 → composables胶水层接收 → 调用core领域层执行业务计算 → 计算结果返回胶水层更新响应式 → 视图自动重新渲染

## 领域层

业务对象、业务规则

1. **接口层 / 应用层**：接收请求、事务编排、调用领域层、调用仓储，**不写业务规则**
2. **领域层 Domain（核心！你刚才那一堆全部放这里）**
   - 聚合根 Aggregate Root
   - 实体 Entity
   - 值对象 ValueObject
   - 领域服务 DomainService
   - 领域事件 DomainEvent
3. **基础设施层**：仓储 Repository 实现、数据库、消息队列、外部 API

```txt
[前端页面/浏览器] 
       │ 
       │ 1. 发送 HTTP 请求 (例如: GET /api/user/1)
       ▼
[后端服务器] (如 Node.js / Express, Java, Python 等)
       │ 
       │ 2. 校验身份与权限 (比如检查 Header 里的 Token/Cookie)
       │ 3. 执行业务逻辑，拼接 SQL 语句
       ▼
[数据库] (如 MySQL, MariaDB, MongoDB)
       │ 
       │ 4. 数据库执行 SQL 并返回查询结果
       ▼
[后端服务器]
       │ 
       │ 5. 将结果清洗/脱敏，封装成 JSON 响应
       ▼
[前端页面/浏览器] (接收到 JSON 响应并渲染页面)
```
