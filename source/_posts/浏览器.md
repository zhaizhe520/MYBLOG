多进程架构

```txt
浏览器知识体系
├─ 五大核心模块
│  ├─ UI界面
│  ├─ 浏览器引擎（调度）
│  ├─ 网络模块（http、缓存、跨域）
│  ├─ 渲染引擎（关键渲染路径、回流重绘合成）
│  └─ JS引擎（V8、JIT、GC、事件循环）
├─ Chrome多进程模型（进程、线程、IPC通信）
├─ 安全体系（同源策略、CORS、XSS、CSRF、沙箱）
├─ 存储体系（cookie、localStorage、indexedDB、CacheAPI）
├─ 性能优化（加载优化、渲染优化、内存优化）
└─ DevTools调试、浏览器标准规范
```

```txt
用户界面层
   ↓ 用户操作
浏览器引擎层
   ↓ 调度
网络与存储层 → 获取资源 / 缓存 / 存储
   ↓
渲染引擎层 → 解析 / 布局 / 绘制 / 合成
   ↑
JavaScript 引擎与执行层 → 操作 DOM / CSSOM / 发请求
```

*用户界面 UI → 浏览器引擎 (调度中枢) → 网络模块 → 渲染引擎 → JS 引擎*

# 浏览器引擎

Chromium 的 Browser Process

浏览器引擎层是浏览器的“总调度中心”。它连接用户界面层、渲染引擎层、网络层、JS 执行层。

主要职责

接收用户界面层的指令

<details>
<summary>渲染引擎 (Rendering Engine)</summary>

DOM 树 + CSSOM 树 → Render 树 → Layout → Paint → Composite

```txt
HTML → DOM
CSS → CSSOM
DOM + CSSOM → Render Tree
Render Tree → Layout
Layout → Paint
Paint → Composite
Composite → 屏幕像素    
```

## 解析 HTML

字节流 → 字符流 → Token → Node → DOM 树 

字节流: 协议变成2进制

字符流:  根据 `charset`（html meta、http 响应头），把字节按 UTF-8 / GBK 解码 → **文本字符**。

/*词法分析，Lexer 词法扫描器*/

token : 最小语法单元 

遇到`<script>` 可能阻塞解析

遇到` <style> `会构建 CSSOM

预加载扫描器会提前发现资源

## 解析 CSS

CSS 字节流 → CSSOM

CSS 是渲染阻塞资源

选择器匹配影响样式计算性能

## 构建渲染树

DOM + CSSOM → Render Tree 

不包含 display: none 节点

包含伪元素、可见节点

## 布局

计算每个节点的几何信息

位置、大小、盒模型

回流/重排

## 绘制

生成绘制指令

填充颜色、文字、边框、阴影、图片

重绘

## 合成

分层

栅格化

合成到屏幕

GPU 加速

合成层、will-change、transform

</details>

# JavaScript 引擎 (JS Engine)

JS 引擎不是独立进程，和渲染引擎**在同一个渲染进程的主线程**

JS 操作 DOM，本质是调用渲染引擎暴露的 DOM API。
