硬盘是以 “页（Page）” 为单位来存东西的

一句话直接给你对齐概念：不是！哈希表的下标是一个纯粹的“数字房间号”（物理内存偏移量）；

而 B+树的索引，在物理硬盘里长相要复杂得多，它是“一个排好序的键值对（Key） + 一张指向硬盘格子的物理地图（指针）”。

当你给 username 字段加了索引，数据库在 B+树 的上层文件夹（非叶子节点）里存的“索引”，实际上是一排排紧密排列的小格子，每个小格子里面雷打不动地只装两个东西：

Key（键值）：你用来查重的依据。比如用户名的字符串 "Murasame"，或者用户 ID 105。

Pointer（指针）：这不是内存里的物理地址，而是“硬盘数据页的页号 + 偏移量”（类似于：第 4096 号硬盘扇区，从上网上数第 5 行）。

| Pointer ID 区间 | 硬盘数据页 |
| --------------- | ---------- |
| ID < 100        | 第2块数据页 |
| 100 ≤ ID < 500  | 第3块数据页 |
| ID ≥ 500        | 第4块数据页 |

# 现在你在后端发起请求：WHERE id = 350。

大厨（CPU）把上面这张“根节点”的索引页从硬盘读进内存。

大厨拿着 350 一对比，发现它落在了 100 <= ID < 500 这个区间里。

指路牌大喊：“别在第一层愣着了！快去读硬盘的第 3 块数据页！”

# 第 2 步（来到中间层，继续看更精细的指路牌）：大厨顺着指针，去硬盘把 第 3 块数据页 读进来。

打开一看，里面是更精细的指路牌：100 <= ID < 300 ----> 去第 8 页300 <= ID < 500 去第 9 页大厨一看，350 属于第二个区间，立刻动身：“快！去硬盘把第 9 块数据页给我搬过来！”


# 第 3 步（来到最底层，抓到真身）：

大厨把 第 9 块数据页（也就是最底层的叶子节点）读进内存。

这里面可就不是指路牌了，这里面整整齐齐躺着的就是真正的人类数据档案！

大厨在这一页里用二分查找扫了一下，当场抓获：ID = 350, username = 'Murasame', age = 18！
