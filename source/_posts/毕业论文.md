# 接入数字人需求

全栈 + PixiJS（交互式网页/动效网页） 是一个非常绝妙且高护城河的方向。

我设计并实现了一个基于解耦架构的、具备高性能 Canvas 渲染能力的交互式 Web 系统（比如 Live2D 桌面宠物、互动式个人博客、或者可视化数据看板）”。

后端有 Nginx 运筹帷幄、前端有 PixiJS 负责视觉，论文的架构图一画，渲染流程图一贴


静态资源的按需加载与优化（和你的图床完美契合）：

PixiJS 最大的痛点就是图片、纹理、骨骼动画（如 Spine / Live2D）资产非常大，首屏加载慢。你之前搞定的 GitHub 图床 + Nginx 缓存 简直是神来之笔！你可以在论文里大写特写：如何通过 Nginx 的反向代理、静态资源缓存控制

以及第三方 CDN 统一分发，来优化 PixiJS 交互网站的资产加载速度。

数据驱动的交互（State Management）：

怎么把后端的 API 数据，优雅地传递给 PixiJS 的渲染循环（Ticker）？

比如利用 Pinia 做全局状态管理，后端传过来一个状态，PixiJS 里的角色立刻做出相应的动画反馈。

这种“业务状态”与“渲染引擎”的解耦连接，是全栈交互网站核心。
