# 编程范式（FP）

`尽量把【计算逻辑】写成纯函数；把【副作用】单独拎出来，统一管理。`

核心：**纯函数、无副作用、输入输出依赖参数，不依赖外部 this，复用逻辑**

# IoC：Inversion of Control 控制反转 思想

你不要自己创建依赖，交给容器/框架来创建，然后送给你。

好莱坞原则: Don't call us, we'll call you.

# DI：Dependency Injection 依赖注入 实现ioc的思想  类的di注入

```ts
  // 依赖：UserRepository （被注入的类）
  class UserRepository {
    findUser(id: number) {
      return { id, name: "张三" }
    }
  }

  // 业务类 UserService，不自己 new UserRepository！ 你要自己new 不是要exdens继承一下这个父类的东西吗？
  class UserService {
    // 构造器注入：外部传入依赖
    constructor(public repo: UserRepository) {}

    getUserInfo(id: number) {
      return this.repo.findUser(id)
    }
  }

  // ========== 外部组装依赖（DI）==========
  // 外部new依赖，传给UserService
  const repo = new UserRepository()
  const service = new UserService(repo) 

  console.log(service.getUserInfo(1))
  ```

## 接口的di注入

```ts
  // 定义接口：只规定需要的方法签名，不写实现
  interface IUserRepo {
    findUser(id: number): { id: number; name: string }
  }

  class UserRepository implements IUserRepo {
    findUser(id: number) {
      return { id, name: "张三" }
    }
  }

  // 重点：这里类型标注改成接口 IUserRepo，不再写 UserRepository
  class UserService {
    constructor(public repo: IUserRepo) {} // ✅ 类型是接口
    getUserInfo(id: number) {
      return this.repo.findUser(id)
    }
  }

  // 正常使用
  const repo = new UserRepository()
  const service = new UserService(repo) 
  ```

“被动符合契约” 与 “主动声明契约”

| 对比项 | 维度仅依赖接口参数类型（不写 implements） | 显式写 class Impl implements Interface |
| ---- | ---- | ---- |
| 契约判定时机 | 延迟校验（直到你把类 new 出来传给 UserService 时才检查） | 即时校验（写 Class 代码的瞬间就立马检查） |
| 错误归属者 | 使用方报错（UserService 处弹红线，报错信息可能很长很绕） | 实现方报错（UserRepository 处直接弹红线，精准定位） |
| 重构与补全 | ❌ 没有代码自动补全，改了接口方法名难以自动定位修改 | ✅ 支持 VS Code / Cursor 一键生成接口方法存根，重构更安全 |

# 迭代 迭代器  枚举 iterator

迭代就是：一个对象只要实现了 [Symbol.iterator]()，返回一个带 next() 的迭代器，它就能被 for...of、展开、解构等统一消费。数组、Map、Set、字符串有；普通对象默认没有。核心是面向协议编程，不是面向具体数据结构编程。

迭代的架构是：用最小协议把“数据源”和“遍历过程”分离，用外部拉取模型把推进控制权交给消费者，用语法糖统一消费方式，用生成器降低状态机实现成本，用异步协议扩展到异步世界。

```txt
数据源
  ├─ Array / Set / Map / String / DOM 集合
  ├─ 自定义对象：实现 [Symbol.iterator]
  └─ 生成器 / 异步生成器

        ↓ 实现可迭代协议

Iterable 可迭代对象
        ↓ [Symbol.iterator]()

Iterator 迭代器（有状态游标）
        ↓ next() 反复调用

IterationResult { value, done }
        ↓

消费端
  ├─ for...of
  ├─ 展开 / 解构 / Array.from
  ├─ Map/Set 构造
  └─ 自定义算法：map/filter/take/sum
```

```js
for (let i = 0; i < n; i++) {
  // 普通索引循环
}

for (const key in obj) {
  // 遍历可枚举属性名/键，常见于对象；不建议直接用于数组
}

for (const value of iterable) {
  // 遍历可迭代对象的值：数组、字符串、Map、Set 等
}
```

每种数据结构遍历方式不同：数组看下标，Map 看 entry，Set 直接给值，树要递归。

```js
const range = {
  from: 1,
  to: 5,

  // 可迭代协议：调用它返回一个迭代器
  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;

    // 迭代器协议：必须有 next()
    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
};

for (const n of range) {
  console.log(n); // 1 2 3 4 5
}

console.log([...range]); // [1, 2, 3, 4, 5]
```
