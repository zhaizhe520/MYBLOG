  # DI：Dependency Injection 依赖注入 实现ioc的思想

  ## 类的di注入

  ```ts
  // 依赖：UserRepository （被注入的类）
  class UserRepository {
    findUser(id: number) {
      return { id, name: "张三" }
    }
  }

  // 业务类 UserService，不自己 new UserRepository！ 你要自己new 不是要exdens继承一下这个父类的东西吗？
  class UserService {
    // 构造器注入：外部传入依赖
    constructor(public repo: UserRepository) {}

    getUserInfo(id: number) {
      return this.repo.findUser(id)
    }
  }

  // ========== 外部组装依赖（DI）==========
  // 外部new依赖，传给UserService
  const repo = new UserRepository()
  const service = new UserService(repo) 

  console.log(service.getUserInfo(1))
  ```

  ## 接口的di注入

  ```ts
  // 定义接口：只规定需要的方法签名，不写实现
  interface IUserRepo {
    findUser(id: number): { id: number; name: string }
  }

  class UserRepository implements IUserRepo {
    findUser(id: number) {
      return { id, name: "张三" }
    }
  }

  // 重点：这里类型标注改成接口 IUserRepo，不再写 UserRepository
  class UserService {
    constructor(public repo: IUserRepo) {} // ✅ 类型是接口
    getUserInfo(id: number) {
      return this.repo.findUser(id)
    }
  }

  // 正常使用
  const repo = new UserRepository()
  const service = new UserService(repo) 
  ```

  “被动符合契约” 与 “主动声明契约”

  | 对比项 | 维度仅依赖接口参数类型（不写 implements） | 显式写 class Impl implements Interface |
  | ---- | ---- | ---- |
  | 契约判定时机 | 延迟校验（直到你把类 new 出来传给 UserService 时才检查） | 即时校验（写 Class 代码的瞬间就立马检查） |
  | 错误归属者 | 使用方报错（UserService 处弹红线，报错信息可能很长很绕） | 实现方报错（UserRepository 处直接弹红线，精准定位） |
  | 重构与补全 | ❌ 没有代码自动补全，改了接口方法名难以自动定位修改 | ✅ 支持 VS Code / Cursor 一键生成接口方法存根，重构更安全 |
